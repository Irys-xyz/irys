What it does

This PR vendors the third-party explain-diff skill into .agents/skills/explain-diff/SKILL.md#L1 and adds a new GitHub Actions workflow, .github/workflows/pr-explain.yml#L1, that runs the skill against every same-repository pull request: once in expert mode when the PR is opened, and once in summary mode when it is merged.

Each run has Claude Code read the PR's diff, title/description, and commit messages from pre-staged files, explore the checked-out tree, and write a single self-contained HTML page. The page is copied to the gh-pages branch under dev/explain/<pr>/<stage>.html, and a sticky bot comment on the PR links to whichever stage(s) exist so far.

Why

Stated intent, from the PR description: "Before: No automated PR explanation; reviewers reconstruct intent from the raw diff, and merged PRs leave no summary. After: The PR Explain workflow runs vendored explain-diff on open (expert) and merge (summary), publishes HTML to gh-pages/dev/explain/<pr>/<stage>.html, and adds a sticky PR comment linking both."

Behavior changes

  • Opening a same-repository PR → previously nothing happened automatically; now an expert-mode HTML page is generated and published to https://<owner>.github.io/<repo>/dev/explain/<pr>/opened.html, linked from a sticky PR comment (see .github/workflows/pr-explain.yml#L45 for the trigger).
  • Merging a same-repository PR → previously no durable summary was left behind; now a summary-mode HTML page is generated and published to .../merged.html, only when pull_request.merged == true (a closed-without-merge PR produces nothing), per .github/workflows/pr-explain.yml#L60.
  • Fork PRs → no change: the job's if condition requires head.repo.full_name == base.repo.full_name, so external contributions never trigger this workflow or consume ANTHROPIC_API_KEY, per .github/workflows/pr-explain.yml#L60.
  • Local development → contributors gain a new /explain-diff [mode] [target] skill they can invoke directly (outside CI mode), documented at .agents/skills/explain-diff/SKILL.md#L28; this does not require the new workflow.
  • A maintainer can also manually (re)generate either page for any same-repo PR via workflow_dispatch, choosing the stage and overriding the mode, per .github/workflows/pr-explain.yml#L14.

Watch out for

1. .github/workflows/pr-explain.yml#L196 — for this very PR (the one introducing the skill), base_sha predates the skill's existence on the base branch, so the bootstrap fallback at line 198 uses the PR's own, still-unmerged copy of SKILL.md to explain itself, instead of a base-branch-trusted copy. That is a deliberate, same-repo-only exception per the inline comment, but it means the "opened" page for PR #1566 was generated under weaker instruction-provenance guarantees than every PR after it — worth confirming the ::warning:: at line 199 actually surfaced in that run's log.
2. .github/workflows/pr-explain.yml#L297 — Claude Code runs with Write access to the entire checkout while summarizing attacker-controllable content (pr.diff/pr.md/commits.txt come straight from the PR under review). The only backstop against a successful prompt injection writing outside .pr-explain/out/ is the git status --porcelain check in the very next step (.github/workflows/pr-explain.yml#L306). That guard only works because "Validate explanation output" unconditionally runs before "Publish page to gh-pages" — a future reorder, an added continue-on-error, or a step inserted between them that touches git state would silently remove the only check standing between an injected write and a push to gh-pages. (Worth a dedicated code-review pass if this trust boundary is safety-critical.)
3. .gitignore#L23 — the .pr-explain/ staging directory this workflow creates is not itself added to .gitignore. A contributor who follows the skill's own "CI mode" instructions locally (as this very explanation-generation session did) is left with an untracked .pr-explain/ directory in git status. Low severity — actions/checkout's default clean step wipes it between CI runs — but it's a minor rough edge for local use.
